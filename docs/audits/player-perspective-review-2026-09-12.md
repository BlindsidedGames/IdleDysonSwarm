# Player perspective and save regression review — 12 September 2026

No introduced gameplay or save regression was found in the exercised baseline/candidate comparisons. This review nevertheless found **two pre-existing save defects**, so overall acceptance is not a blanket pass. Neither defect was changed during this review.

Baseline production source remains at 4.1.8, `878f5bffecd59c699712103172e668d12853d16a`; candidate is `7bc88cd7c8045e48675e343ed2374a0cfd8706d7`. Browser runs used the frozen baseline web build and candidate v6 build, disposable profiles and fixture copies. Eligible late-game actions used explicitly funded synthetic states. These are eligibility tests, not evidence that each state was reached through natural play.

## Findings

1. **[P2] Reset Skills can restore its cleared live auto-assignment queue after saving/reloading.** Both versions persist the refunded ownership correctly, but an old compatibility queue survives dehydration and repopulates the cleared canonical queue during preparation. A strengthened browser test first checkpointed four owned skills, verified that sentinel by reload, then reset and waited 31.5 seconds without Export. Reload preserved empty ownership but restored all four queue IDs. An independent pure-source reproduction matched exactly in both versions. This is separate from intentionally retaining saved presets. It demonstrates restored assignment intent, not observed subsequent purchases or resource loss. See [mechanism and reproduction](player-save-review-2026-09-12.md#p2-pre-existing-resetting-skills-can-revive-its-cleared-queue-after-reload).
2. **Legacy IDB1 imports do not validate the gzip CRC32 trailer.** Both versions accepted five otherwise valid historical envelopes with damaged CRCs. A controlled follow-up changed one date field while retaining a stale checksum: both accepted it, whereas Node zlib rejected it. Canonical IDSWEB1 imports rejected equivalent checksum damage. This is a legacy corruption-detection gap, not evidence of new data loss. See [legacy checksum evidence](player-save-review-2026-09-12.md#pre-existing-finding-legacy-idb1-crc32-is-not-validated).

An abrupt reload before the regular 30-second checkpoint can recover earlier progress in both versions. Export fences dirty state, so export-then-reload evidence is reported separately from automatic saving. The initial weak autosave oracle was rejected during independent review and replaced with the nonempty checkpoint test above; its earlier apparent pass is not accepted evidence.

## Save-file and durable-storage evidence

- **382/382 candidate and 379/379 baseline focused tests passed**, plus **474 independent full-graph/byte/error/operation-trace comparisons**. These include historical inputs, exact export bytes, cross-imports, migration, size/corruption boundaries, cloud startup and injected commit failures. All six failed commit scenarios preserve current-save bytes. See the [save review](player-save-review-2026-09-12.md).
- **18/18 browser fixture/build cases passed**: import, export, reload, corrupt import rejection with progress retained, Reset Save cancellation, confirmed fresh reset and restoration from exported bytes. Expanded stable markers distinguish all nine fixtures and cover ownership, research, automation/allocation, Skills/presets, Infinity/Quantum, Reality unlock, Dream/education, Avocado, challenges and stored-time capacity. Live accrual is excluded; this is selected stable progression preservation, not full save-byte equality.
- **24/24 transfer checks passed**: 18 cross-build imports covering all nine fixtures in both directions, exact downloaded and copied export bytes, and import through the actual file input. Cross-build UI markers are narrower than the expanded same-build markers; full-byte/full-graph compatibility is covered by the independent differential suite. The native OS file-picker window itself was not automated.
- **8/8 real IndexedDB checks passed**: second-tab takeover preserves selected progression, the former writer loses gameplay UI, a corrupt primary recovers from a valid backup, and a future-schema primary blocks startup while its exact bytes remain intact despite available backups. Faults were injected only into isolated test storage with app pages inactive.
- **Stored Time passed in both builds**: arm/cancel, one-minute spend, Repeat, cancel while running and Speed Up have the expected bank accounting. Separate reloads without a preparatory Export preserve completed/cancelled job bank values, allowing up to two seconds of legitimate offline accrual. This does not assert rollback of every field from the browser bank check alone.
- **Automatic Skills saving exposes finding 1**: ownership durability passes; queue-clearing durability fails in both builds. It is not included in an all-passing save aggregate.

Legacy browser import follow-up: all five selected historical files imported and exported through each build. Eight of ten raw-preparation versus live-export stable-marker comparisons matched exactly; support-case-01 gained two skill points identically in both builds. An independent source reproduction confirmed that goal catch-up completes stages 2 and 3, awards exactly two points, preserves owned skills and awards zero on a second pass in both builds. The two raw-marker exceptions therefore reflect existing idempotent gameplay progression; they remain distinguished from the eight exact raw-marker passes.

## Boundaries and delivery

No production code changed during this additional review, and no merge, push or deployment was performed. The primary checkout acquired an unrelated untracked `AGENTS.md` during the review; it is not claimed to have an entirely clean working tree. Audit documents and local ignored reproduction artifacts were added. Existing defects are reported for a separate fix that can preserve historical imports and saved presets.

The review does not exhaust every numerical state, arbitrary action ordering, natural challenge completion, all locale content, OS file-dialog behavior, native purchases/restores, real cloud accounts, every storage/quota failure or physical-device lifecycle interruption. External website/Discord links were not followed. The static inventory, rendered inventory, pointer delivery and exact gameplay comparisons are complementary evidence and are not summed into an invented total of fully tested buttons.

Raw parent scripts/results are in `output/player-review/` under `save-browser`, `save-transfer-browser`, `storage-browser`, `offline-browser`, `offline-durable-browser`, `debug-browser`, `surface-sweep`, `legacy-browser` and `targeted-purchases.json`. The compact [machine summary](player-perspective-review-2026-09-12.json) retains the parent observations without copying the large save corpus into tracked documents. Independent reviewers challenged the source changes, browser assertions and final report; limitations discovered during that review are retained above.
